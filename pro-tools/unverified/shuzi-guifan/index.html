一、工具简介

  
本工具依据 GB/T 15835-2011《出版物上数字用法》，对中文文本中的数字用法进行规范性校验与转换。解决的核心问题是：编辑、记者、公文撰写者在处理数字时，常常混淆阿拉伯数字与汉字数字的使用场景，导致出版物不符合国家标准。

  
工具覆盖的主要规则包括：公元纪年、干支纪年、农历日期、物理量量值、概数与约数、序数、编号、统计数值等的正确写法，并提供正误对比示例。


  
二、核心函数与参数说明


  
1. checkNumberUsage(text)

  
主入口函数，对输入文本进行全面校验。

  

    
参数类型取值范围含义

    
textstring任意字符串待校验的中文文本

  

  
返回值：{ valid: boolean, issues: Array, statistics: Object }

  
    
    
  • valid：是否完全符合规范
    • 
    
  • issues：问题列表，每项含 rule（规则编号）、location（位置）、original（原文）、suggestion（建议）
    • 
    
  • statistics：统计信息（阿拉伯数字个数、汉字数字个数等）
    • 
  


  
2. chineseToArabic(str)

  
将汉字数字转换为阿拉伯数字。

  

    
参数类型取值范围含义

    
strstring由"零一二三四五六七八九十百千万亿"组成的字符串汉字数字

  

  
返回：number。若输入非法抛出 TypeError。


  
3. arabicToChinese(num, mode)

  
将阿拉伯数字转换为汉字数字。

  

    
参数类型取值范围含义

    
numnumber非负整数，建议 ≤ 9999999999999阿拉伯数字

    
modestring'lower' | 'upper'小写（一二三）或大写（壹贰叁）

  


  
4. isGanzhiYear(str) / isGregorianYear(str) / isLunarDate(str)

  
识别类函数，返回 boolean。分别判断是否为干支纪年、公元纪年、农历日期。


  
5. isPhysicalQuantity(str)

  
判断是否为物理量量值（数字 + 单位），物理量中的数值应使用阿拉伯数字。


  
6. isApproximateNumber(str)

  
判断是否为概数（如"三四天""十七八岁"），概数应使用汉字数字。


  
三、完整使用场景


  
场景 1：公元纪年校验

  
输入："二〇二四年十月一日，中华人民共和国成立七十五周年。"

  
结果：检出问题 —— 公元纪年应使用阿拉伯数字。

  
建议修改："2024年10月1日，中华人民共和国成立75周年。"

  
依据：GB/T 15835-2011 第 4.1.1 条，公元纪年应使用阿拉伯数字。


  
场景 2：干支纪年校验

  
输入："2024年是甲辰年。"（此处"甲辰年"正确）

  
错误示例："甲辰年是二〇二四年。"（公元纪年误用汉字）

  
建议修改："甲辰年是2024年。"


  
场景 3：物理量量值校验

  
输入："体重约一百二十斤，身高一点七五米。"

  
结果：检出问题 —— 物理量数值应使用阿拉伯数字。

  
建议修改："体重约120斤，身高1.75米。"

  
依据：GB/T 15835-2011 第 4.1.2 条，物理量量值中的数值应使用阿拉伯数字。


  
场景 4：概数校验

  
输入："参加人数约34人，年龄在178岁之间。"

  
结果：检出问题 —— 相邻数字连用表示概数时应使用汉字。

  
建议修改："参加人数约三四十人，年龄在十七八岁之间。"

  
依据：GB/T 15835-2011 第 4.2.1 条。


  
场景 5：农历日期校验

  
输入："今天是8月15（农历）。"

  
结果：若指农历日期，应使用汉字。

  
建议修改："今天是八月十五（农历）。" 或 "今天是农历八月十五。"


  
场景 6：序数校验

  
输入："第三十届奥运会。"

  
说明：GB/T 15835-2011 允许"第三十"或"第30"两种写法，均合规。

六、局限性说明

  
    
    
  1. 上下文理解有限：本工具基于正则与规则匹配，无法完全理解语义上下文。例如"第一"在"第一次"中是序数，在"第一产业"中是分类编号，工具可能给出相同建议。
    2. 
    
  2. 不处理文学修辞：文学作品中为修辞效果故意使用的数字（如"白发三千丈"）会被误判为不规范，需人工复核。
    3. 
    
  3. 不覆盖所有行业规范：某些行业（如法律、金融、科技）有专门的数字用法细则，本工具仅覆盖通用出版物规范。
    4. 
    
  4. 繁体与异体字：对繁体数字（如"壹贰叁"）仅支持大写模式识别，小写繁体（如"壹"作小写用）需查标准原文确认。
    5. 
    
  5. 不处理排版细节：如"年份不能拆分移行"属于排版规则，本工具仅做文本层面提示，不介入实际排版引擎。
    6. 
    
  6. 不保证100%准确：任何规则引擎都无法替代专业编辑的人工判断，本工具定位为辅助工具。
    7. 
    
  7. 部分边界案例需查标准原文：如含"几"字的概数（"几天""十几岁"）的具体写法，标准中有细致规定，本工具仅做基础识别。
    8.
